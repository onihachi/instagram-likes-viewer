# 実装判断 — 0.2.0

2026-10-01、ユーザーの承認を受け、正規Chrome操作ツールでログイン済みの公式いいね一覧を調査した。実カードはmain article内のラベル付きbuttonで、投稿URLのアンカーはなかった。通常操作で投稿を開いて戻ると元の一覧位置が失われた。iframe表示も利用できなかったため、元の一覧を残して公式投稿URLを別ウィンドウに開く方式へ変更した。

カードの画像URLに含まれるig_cache_keyを復号し、数値media IDからshortcodeを計算する。動画の連結IDは候補prefixの時刻と表示投稿日が一致する一意な候補だけを採用する。未解決カードは通常遷移を止め、停止して通常操作へ戻せる案内を出す。カルーセルの子IDは公式ページ自身が親投稿URLへリダイレクトすることを実機で観測した。解決済みURLはセッションのメモリに保持する。

ユーザーのクリックからwindow.openを実行する。親一覧のDOMとスクロール祖先の位置を保存し、子ウィンドウに×ボタンとEsc処理を加える。閉じる際はvideo/audioをpauseし、子ウィンドウを閉じ、親のフォーカスと位置を復元する。ウィンドウ自体の閉鎖も監視する。実カード経路では親の履歴を追加しない。

従来の通常アンカーに対するiframe dialog・履歴marker処理は互換経路として残している。架空デモとそのモック試験は実Instagramの別ウィンドウ経路とは区別する。

権限はactiveTab+scriptingのみ。Cookie、ストレージ、非公開API、CSPや埋め込み制限の書き換えは使用しない。画像URLは表示済みDOMから読み、独自の通信・全履歴取得はしない。

chrome://extensionsはChrome操作ツールのポリシーで操作できなかったため、導入と更新はユーザーの手動操作で行った。追加権限は要求していない。
